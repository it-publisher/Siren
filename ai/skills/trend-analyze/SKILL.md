# trend-analyze

> **Статус:** работает. Проверен на настоящей недельной выборке.

## Назначение

Выявить повторяющиеся приёмы и превратить их в идеи рилсов.

## Вход

`trends/<YYYY-MM-DD>/music/` с роликами и `notes.md`: ссылки, просмотры, звуки. Если роликов меньше трёх, скажи об этом: вывод о приёмах будет слабым.

## Шаги

1. Снять замеры каждого ролика из `engine/`:

   ```bash
   cd engine
   D=../trends/<YYYY-MM-DD>/music
   for F in "$D"/*.mp4; do npm run --silent analyze-video -- --video "$F" --out "$D/analysis/$(basename "$F" .mp4)"; done
   ```

   В `analysis/<ролик>/metrics.json` лежат размер, длительность, склейки, средняя длина плана и громкость, в `frames/` кадр каждые 2 с. Для быстрого монтажа уменьши шаг: `--frame-every 0.5`. Детектор склеек не видит плавные переходы и может ошибиться на вспышках, поэтому сверяй число планов по кадрам.
2. Открыть кадры и разобрать каждый ролик: крючок, темп, подписи, структуру, призыв к действию.
3. Если важна речь, снять её: `npm run transcribe -- --audio <wav> --out <json> --language <ru|en>`. Whisper ошибается в словах, такую цитату помечай как распознанную.
4. Сопоставить приёмы с `formats/README.md` и с результатами своих рилсов из карточек в `published/`.
5. Заполнить `report.md` по `templates/trend-report.md`. Измерения отдельно, догадки с пометкой.
6. Показать идеи пользователю. Отчёт можно указать в поле `trend_report` следующего брифа.

## Выход

`trends/<YYYY-MM-DD>/music/report.md`, замеры в `analysis/` вне git.

## Проверки

- Выводы опираются на несколько роликов, а не на один.
- Догадки отделены от измерений.
- Числа в отчёте совпадают с `metrics.json`.
