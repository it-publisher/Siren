# scene-plan

> **Статус:** работает для `talking-closeup` и `story-clip`. Остальные форматы пока только разобраны, у них нет схемы и шаблона: если формат другой, останови работу и скажи об этом пользователю. Скиллом целиком ещё не прогонялся, схема и сборка проверены на ручных запусках.

## Назначение

Превратить план съёмки в описание сцен, по которому шаблон соберёт ролик.

## Вход

`brief.yaml`, `formats/<slug>/format.md`. Для `talking-closeup` ещё `script.md` и `timing/words.json`. Для `story-clip` ещё `timing/beats.json`.

## Шаги

1. Прочитать в `format.md` механику и схему `scenes.json`. У каждого формата своя схема.
2. Составить файл по правилам формата.

   **`talking-closeup`.** Один план, поля по схеме формата: `videoFile`, `audioFile`, `wordsFile`. В `shot-plan.md` одна строка: крупный или средний план, поёт весь фрагмент.

   **`story-clip`.** Сначала `shot-plan.md`: таблица «№, секунды, поёт или нет, крупность, место, действие, движение камеры, кадр». Таблицу утверждает пользователь до генерации.
   - Средние и крупные планы. Широкий предлагай только с оговоркой, что пока он выглядит как ИИ.
   - `seconds` подбирай так, чтобы склейка попала на бит из `timing/beats.json`. Сумма `seconds` равна длине `audio/fragment.wav`.
   - `audioFile`: `audio/fragment.wav`. `look`: по умолчанию `film`, этот вариант выбрал пользователь. `film-strong` только по просьбе.
   - `sway: true` ставится на неподвижные поющие планы. На планах с движением камеры покачивание не нужно.
   - В `videoFile` заранее пиши будущие пути `clips/<NN>-<slug>.mp4`, они появятся на шаге `/clip-generate`.

3. Проверить файл по схеме. Из `engine/` собрать один кадр композиции формата: `TalkingCloseup` или `StoryClip`. Для форматов с клипами эта проверка делается после `/clip-generate`, когда клипы уже лежат в запуске. Ошибки схемы команда выведет и завершится с ненулевым кодом. `remotion compositions` не подходит: она проверяет сразу все форматы и падает на чужих `scenes.json`.

   ```bash
   cd engine
   npx remotion still StoryClip ../work/<run-id>/checks/first-frame.png --frame=0 --public-dir=../work/<run-id> --log=error
   ```

4. Для `talking-closeup` посмотреть кадры с длинными подписями. Номер кадра: `startMs` слова из `words.json` × 30 / 1000, он передаётся в `--frame`.
5. Показать план пользователю.

## Выход

`scenes.json`, `checks/first-frame.png`, `shot-plan.md`.

## Проверки

- Команда шага 3 завершилась без ошибок.
- Нет обрезанного текста на кадрах из шага 4.
- Для `story-clip`: сумма `seconds` совпадает с длиной фрагмента, отклонение до 0,1 с.
