# publish-package

> **Статус:** работает. Отправка в Siren Publisher проверена на тестовом рилсе. Без настроенного публикатора скилл работает по-старому: всё готовится, а публикуешь ты сам. Автозапуск выключен, так как шаг ведёт к публикации.

## Назначение

Перенести результат в `published/`, написать подписи по площадкам и отправить рилс в Siren Publisher. Публикатор присылает карточку в Telegram-бот, и рилс уходит на площадки только после апрува владельца. Как это устроено: [гайд по публикации](../../../docs/guides/publishing.md).

## Вход

`work/<run-id>/` с `render/final.mp4` и `checks/report.md`.

## Шаги

1. Проверь, что отчёт есть и в нём нет открытых дефектов, а в карточке нет нерешённых отметок. Если команда ниже что-то нашла, остановись и покажи это пользователю.

   ```bash
   grep -n "⚠️" work/<run-id>/card.md
   ```

2. Заполни в `card.md` расходы.
3. Напиши подписи в `work/<run-id>/platforms.json` голосом персонажа: прочитай `accounts/music/brand.md` и описание персонажа из `characters/<имя>/`. Формат и лимиты — в [гайде](../../../docs/guides/publishing.md#подписи). Значения по умолчанию:
   - `telegram_story` включена. Подпись короткая, одна-две строки.
   - `instagram` включён. Подпись — основной текст, хэштеги в конце, не больше 30.
   - `youtube` **выключен**: на бесплатном тарифе Upload-Post 10 загрузок в месяц. Заголовок и описание всё равно напиши, чтобы его можно было включить.
   - `tiktok` всегда `enabled: false`: TikTok пользователь выкладывает руками, подпись попадёт в `caption-tiktok.txt`.
4. Покажи пользователю подписи по площадкам и карточку. Спроси:
   - включить ли YouTube;
   - публиковать сразу после апрува или в заданное время (`--publish-at`).

   ⛔ Без его подтверждения дальше не идём. Правки вноси в `platforms.json`.
5. Проверь пакет без отправки. Если скрипт нашёл ошибки, исправь `platforms.json` и повтори.

   ```bash
   cd engine && npm run send -- --run <run-id> --dry-run
   ```

6. Скопируй файлы из корня репозитория. Файла `script.md` может не быть: он есть только у форматов с подписями.

   ```bash
   RUN=<run-id>; D="published/music/$RUN"; mkdir -p "$D"
   cp "work/$RUN/render/final.mp4" "work/$RUN/brief.yaml" "work/$RUN/scenes.json" "work/$RUN/card.md" "work/$RUN/platforms.json" "work/$RUN/caption.txt" "$D/"
   for F in script.md shot-plan.md caption-tiktok.txt; do if [ -f "work/$RUN/$F" ]; then cp "work/$RUN/$F" "$D/"; fi; done
   ```

7. Отправь рилс. Сначала скрипт забирает результаты прошлых публикаций, затем отправляет пакет.

   ```bash
   cd engine && npm run send -- --run <run-id>
   ```

   - Добавь `--publish-at 2026-12-01T18:30:00+03:00`, если пользователь выбрал время.
   - Если ролик длиннее 60 с, скрипт сам обрежет копию для сторис до 59,5 с. Другую версию можно передать через `--story-video <файл>`.
   - Если команда пишет `Could not resolve hostname publisher-siren`, публикатор на этом компьютере не настроен. Скажи об этом и остановись: файлы уже в `published/`, публикация вручную. Настройка — в [гайде](../../../docs/guides/publishing.md#настройка-компьютера).
8. Скажи пользователю: «Пакет отправлен, карточка придёт в бот». Напомни:
   - метку ИИ на площадках публикатор не ставит: проверить её после публикации и при необходимости поставить в приложении;
   - TikTok выкладывается руками: видео `published/music/<run-id>/final.mp4`, подпись `caption-tiktok.txt`;
   - ссылки и дата публикации появятся в `card.md` при следующей отправке. Забрать их сразу можно командой `cd engine && npm run sync`.
9. Через 1 и 7 дней в `card.md` идут результаты.

## Выход

- `published/music/<run-id>/` с подписями.
- Пакет на сервере публикатора, карточка в боте.
- После публикации: `publish.json` со статусами и ссылками, дата и ссылки в `card.md`.

## Проверки

- Отчёт проверки без открытых дефектов.
- Пользователь подтвердил подписи и площадки.
- `npm run send -- --dry-run` прошёл без ошибок.

## Открытые вопросы

- Требования к метке ИИ известны по пересказам правил Meta: сверить со справкой Instagram.
- Ставят ли площадки метку ИИ сами для рилсов, опубликованных через API, проверяется на первых публикациях.
