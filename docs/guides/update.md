# Гайд: обновление копии

Инструкция для агента. Копия работает без git, поэтому обновление идёт по версиям: агент сравнивает прошлую версию, новую и саму копию и заменяет только файлы движка. Контент пользователя не трогается.

Пользователю достаточно написать агенту: «Обнови Siren до версии vX.Y по инструкции: <ссылка на этот файл>».

---

## Правила

- Git не используй и не создавай `.git`.
- Никогда не меняй контент: `accounts/`, `characters/`, `published/`, `work/`, `trends/`, `ref/`, `assets/`, `ai/context/`, `.env`. Скрипт обновления их не трогает. Правки в `ai/context/` вносятся только вручную по описанию версии и только с согласия пользователя.
- Если что-то не совпадает с инструкцией, остановись и спроси пользователя.
- Обновляй до конкретной версии, а не до последнего состояния `main`.

---

## Шаги

Команды выполняются из корня копии.

1. **Текущая версия.** Если файла нет, копия скачана до появления версий, и это `v1.0`.

   ```bash
   cat VERSION 2>/dev/null || echo v1.0
   ```

2. **Резервная копия** всей папки, кроме зависимостей, которые ставятся заново. Скажи пользователю, где она лежит.

   ```bash
   B=~/Desktop/Siren-backup-$(date +%Y-%m-%d-%H%M); rsync -a --exclude engine/node_modules --exclude engine/.whisper ./ "$B/" && echo "$B"
   ```

3. **Скачай обе версии** во временную папку. `FROM` — текущая версия из шага 1, `TO` — новая.

   ```bash
   FROM=v1.0; TO=v1.1; U=$(mktemp -d)
   for V in "$FROM" "$TO"; do mkdir "$U/$V" && curl -fsSL "https://github.com/it-publisher/Siren/archive/refs/tags/$V.tar.gz" | tar -xz --strip-components=1 -C "$U/$V"; done
   ```

4. **Проверка без изменений.** Скрипт берётся из новой версии.

   ```bash
   node "$U/$TO/engine/scripts/update-copy.mjs" --copy . --base "$U/$FROM" --next "$U/$TO"
   ```

   Покажи пользователю коротко: сколько файлов обновится, добавится и удалится.
5. **Если есть раздел «⚠️ Изменены в копии»**, скрипт ничего не применит. Значит, эти файлы движка в копии правили, или копия скачана не с версии `FROM`. По каждому файлу покажи пользователю разницу и спроси:
   - взять новую версию: `cp "$U/$TO/<файл>" "<файл>"`;
   - оставить свою: `cp "<файл>" "$U/$TO/<файл>"` — тогда файл совпадёт с новой версией, и скрипт его не тронет.

   Повтори шаг 4.
6. **Применить.**

   ```bash
   node "$U/$TO/engine/scripts/update-copy.mjs" --copy . --base "$U/$FROM" --next "$U/$TO" --apply
   ```

7. **Шаги версии.** Открой `docs/updates/$TO.md` и выполни их по порядку. Там же правки контента, если они есть: раздел «Изменились в новой версии, но это контент» из вывода скрипта.
8. **Проверка.**
   - Если в списке обновлённых был `engine/package-lock.json`: `cd engine && npm ci`.
   - `cd engine && npm test` — все тесты проходят.
   - `cat VERSION` показывает новую версию.
9. Удали временную папку: `rm -rf "$U"`. Резервную копию оставь, пока пользователь не проверит работу новой версии.

Сообщи пользователю: где резервная копия, «Siren обновлён до vX.Y» и что осталось сделать по описанию версии.

---

## Откат

Верни папку из резервной копии шага 2, затем `cd engine && npm ci`.

```bash
rsync -a --delete --exclude engine/node_modules --exclude engine/.whisper "$B/" ./
```
