# Гайд: публикация через Siren Publisher

Siren Publisher — отдельный сервис на сервере. Он принимает готовый рилс, присылает владельцу карточку в Telegram-бот и после апрува публикует рилс на площадки. Siren только собирает пакет и отправляет его, ключи площадок на этот компьютер не попадают.

Без публикатора Siren работает как раньше: `/publish-package` готовит файлы, а публикуешь ты сам.

---

## Как это работает

1. `/publish-package` пишет подписи по площадкам и показывает их тебе.
2. После твоего подтверждения скрипт проверяет видео и подписи, собирает пакет и отправляет его на сервер.
3. В бот приходит карточка: видео, подписи, площадки. Можно изменить подпись, выключить площадку, выбрать время или отклонить.
4. После апрува публикатор публикует рилс и присылает отчёт со ссылками.
5. При следующей отправке Siren забирает результаты: `publish.json` и ссылки в `card.md` в `published/music/<run-id>/`.

После отправки подписи правятся в карточке бота кнопкой «Изменить подпись». Повторная отправка того же `run-id` отклоняется как дубль. Для новой публикации скопируй `work/<run-id>` под новым `run-id`, например с суффиксом `-2`:

```bash
cp -R work/2026-11-27-music-night-city work/2026-11-27-music-night-city-2
```

| Площадка | Как публикуется |
|---|---|
| Сторис Telegram | Публикатор, в профиль владельца бота |
| Instagram Reels | Публикатор |
| YouTube Shorts | Публикатор через Upload-Post. Бесплатно 10 загрузок в месяц, поэтому по умолчанию выключен |
| TikTok | Вручную: видео из `published/`, подпись из `caption-tiktok.txt` |
| Страница Facebook | Вручную: «Поделиться» в Instagram после публикации |

## Настройка компьютера

Делается один раз. Адрес сервера и отпечаток его ключа даёт тот, кто обслуживает публикатор: в репозитории их нет.

1. **rsync 3.** Встроенный в macOS rsync не умеет удалять забранные с сервера файлы.

   ```bash
   brew install rsync
   rsync --version | head -1   # rsync  version 3.x
   ```

2. **Ключ для отправки пакетов.** Секретная часть остаётся на этом компьютере, наружу уходит только публичная.

   ```bash
   ssh-keygen -t ed25519 -N "" -C "siren-$(whoami)" -f ~/.ssh/publisher_siren
   cat ~/.ssh/publisher_siren.pub
   ```

3. **Адрес сервера** в `~/.ssh/config`, вместо `<адрес>` — адрес от администратора публикатора:

   ```text
   Host publisher-siren
       HostName <адрес>
       User publisher
       IdentityFile ~/.ssh/publisher_siren
       IdentitiesOnly yes
   ```

4. **Ключ сервера.** Сверь отпечаток с тем, что дал администратор, и только при совпадении добавь его:

   ```bash
   ssh-keyscan -t ed25519 <адрес> 2>/dev/null | tee /tmp/publisher-host | ssh-keygen -lf -
   cat /tmp/publisher-host >> ~/.ssh/known_hosts && rm /tmp/publisher-host
   ```

5. Отправь администратору строку из шага 2 (`ssh-ed25519 AAAA… siren-…`). Он добавит её на сервер с доступом только к папке обмена.
6. **Проверка.** Команда должна закончиться без ошибок и сказать, что новых результатов нет или забрать их:

   ```bash
   cd engine && npm run sync
   ```

## Подписи

Файл `work/<run-id>/platforms.json`. Его пишет `/publish-package`, ты подтверждаешь или правишь.

```json
{
  "telegram_story": { "enabled": true, "caption": "Новый трек уже здесь 🎧" },
  "instagram": { "enabled": true, "caption": "Текст рилса\n\n#music #newmusic", "share_to_feed": true },
  "youtube": {
    "enabled": false,
    "via": "upload_post",
    "title": "Название трека — короткая фраза",
    "description": "Текст рилса\n\n#music #shorts",
    "tags": ["music", "shorts"],
    "privacy": "public"
  },
  "tiktok": { "enabled": false, "caption": "Текст для TikTok #music" }
}
```

| Поле | Лимит |
|---|---|
| `telegram_story.caption` | 2048 символов |
| `instagram.caption` | 2200 символов, до 30 хэштегов и 20 упоминаний |
| `youtube.title` | Обязателен, если YouTube включён. До 100 символов, без `<` и `>` |
| `youtube.description` | До 5000 байт, без `<` и `>` |
| `youtube.tags` | Вместе до 500 символов |
| `tiktok.caption` | 2200 символов |

Дополнительно, по желанию:

- `telegram_story.areas` — кликабельная ссылка в сторис: `{"type": "link", "url": "https://…", "label": "Слушать трек", "position": {…}}`. Подпись `label` до 40 символов публикатор рисует на видео сам.
- `telegram_story.post_to_chat_page: false` — сторис исчезнет через сутки и не останется в профиле.

Скрипт проверяет лимиты до отправки. Окончательную проверку делает публикатор: если пакет не подошёл, причина придёт в бот.

## Команды

Запускаются из `engine/`.

| Команда | Что делает |
|---|---|
| `npm run send -- --run <run-id> --dry-run` | Проверяет видео и подписи, собирает пакет в `work/<run-id>/package/`, ничего не отправляет |
| `npm run send -- --run <run-id>` | Забирает результаты прошлых публикаций и отправляет пакет |
| `npm run send -- --run <run-id> --publish-at 2026-12-01T18:30:00+03:00` | То же, время публикации предложено в карточке |
| `npm run send -- --run <run-id> --story-video <файл>` | Отдельное видео для сторис. Без него ролик длиннее 60 с для сторис обрезается до 59,5 с. Если сторис выключена, файл не используется |
| `npm run sync` | Только забрать результаты |

Видео перед отправкой перепаковывается без перекодирования: служебная часть файла переносится в начало, иначе Instagram его не примет.

## Если что-то пошло не так

| Сообщение | Что делать |
|---|---|
| `Нужен rsync 3` | `brew install rsync` и новое окно Терминала |
| `Permission denied (publickey)` | Ключ ещё не добавлен на сервер или в `~/.ssh/config` не тот файл ключа |
| `Host key verification failed` | Не выполнен шаг 4 настройки |
| `Подписи не прошли проверку` | Исправить `platforms.json` по списку ошибок |
| `нет папки published/music/<run-id>` при заборе результатов | Результат чужого или тестового рилса. Он остаётся в `work/.publisher-outbox/` и ничего не ломает |
| Бот пишет «нужен новый reel_id» | Этот `run-id` уже отправлялся. Подпись правь в карточке бота, для новой публикации скопируй запуск под новым `run-id` |
| Бот пишет, что пакет не принят | Причина в сообщении бота. Исправить и отправить заново под тем же `run-id` |

---

## Безопасность

- Ключ `publisher_siren` открывает только папку обмена на сервере: положить пакет и забрать результат. Командной строки и чужих файлов он не даёт.
- Ключи Instagram, YouTube и Telegram живут только на сервере публикатора.
- Без апрува в боте ничего не публикуется.
