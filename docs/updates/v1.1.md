# v1.1: автопубликация через Siren Publisher

Шаги для агента после `update-copy.mjs --apply` ([гайд по обновлению](../guides/update.md), шаг 7).

---

## Что нового

- `/publish-package` пишет подписи по площадкам и отправляет рилс в Siren Publisher. Публикатор присылает карточку в Telegram-бот и публикует только после апрува: [гайд](../guides/publishing.md).
- `npm run send` и `npm run sync`: отправка пакета и забор результатов в `published/`.
- Обновление копии по версиям: `engine/scripts/update-copy.mjs`, файл `VERSION`.

Зависимости не менялись, `npm ci` не нужен.

## 2. Настройка компьютера для публикатора

Только если пользователь будет публиковать через Siren Publisher. Иначе пропусти: `/publish-package` работает и без него, публикация вручную.

Спроси у пользователя **адрес сервера** и **отпечаток ключа сервера** (`SHA256:…`): их даёт администратор публикатора, в репозитории их нет. Затем выполни раздел «Настройка компьютера» из [гайда по публикации](../guides/publishing.md#настройка-компьютера), шаги 1–5:

1. `brew install rsync`. Homebrew может спросить пароль Mac: попроси пользователя ввести его в Терминале сам, в чат пароль не присылать.
2. Ключ `~/.ssh/publisher_siren`. Если файл уже есть, не перезаписывай, спроси.
3. Блок `publisher-siren` в `~/.ssh/config`. Если блок уже есть, не дублируй, спроси.
4. Ключ сервера. **Отпечаток должен совпасть** с тем, что дал пользователь. Не совпал — остановись и ничего не добавляй.
5. Покажи пользователю публичную строку `ssh-ed25519 AAAA… siren-…` и попроси передать её администратору публикатора. Секретный файл `~/.ssh/publisher_siren` никуда не отправляй.

Когда пользователь скажет, что ключ добавлен, проверь связь:

```bash
cd engine && npm run sync
```

**Готово**, если команда закончилась без ошибок: «Новых результатов нет» или список забранных результатов. Скажи пользователю: «связь с сервером есть».
